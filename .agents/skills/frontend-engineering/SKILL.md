# Senior multi-framework frontend
1. Identify actual framework/version, router/rendering strategy, styling, state/query libraries, linter, test scripts and deployment targets.
2. Match repo idioms: React/Next hooks and server boundaries, Vue composition/options patterns, Svelte stores/runes where supported, or plain browser modules as applicable.
3. Keep UI and domain state separate, API types consistent and effects/cancellation explicit. Check SSR/CSR hydration, accessibility, loading and route errors.
4. Reuse existing primitives and a single visual system; no needless package/theme churn.
5. Validate framework-specific type/lint/test commands and inspect interaction on representative devices.

Don't apply Angular-only instructions when the repository is not Angular. For multiple apps, state exactly which app was modified.
